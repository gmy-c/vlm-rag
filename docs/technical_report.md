# 企业内部多模态大模型算法：基于页面图像的视觉检索增强生成（VLM-RAG）

## （1）需求分析

企业内部存在大量 PDF、PPT、报表、合同、制度、手册等图文混排文档。传统文本 RAG 通常依赖 OCR、版面解析和文本切分，但在真实业务中会遇到三类问题：

1. OCR 识别错误会直接传导到召回和生成阶段，导致答案引用错误。
2. 图表、表格、签章、批注、页眉页脚等视觉信息在文本化后容易丢失。
3. 多页文档的答案常分布在多个页面，单页文本切片难以完成跨页融合。

本项目目标是构建基于页面图像的 VLM-RAG 方案：直接将每一页文档渲染为页面图像，使用视觉语言模型对 Query 与页面图像进行统一向量编码，然后检索 Top-K 页面并交给多模态生成模块完成答案融合。

核心业务指标包括：

- 检索指标：MRR@10、Recall@K。
- 生成指标：EM、Accuracy。
- 效率指标：单页处理耗时。
- 对比基线：OCR RAG、SigLIP、ColPali、图像拼接方案。

目标效果参考：

- 六类文档 MRR@10 达到 77.91，优于 MiniCPM OCR 方案 74.78、SigLIP 71.68、ColPali 76.54。
- Top-3 多页问答平均准确率达到 56.12，优于 GPT-4o OCR 方案 45.91、图像拼接方案 29.36。
- 图文类文档准确率由 25% 提升至 51%，整体指标提升约 40%。
- 单页处理耗时约 121ms，相比 OCR 链路 312ms 提速约 58%。

## （2）数据分析

数据来源包括企业内部 PDF、PPT、财务报表、采购合同、销售复盘、费用单据、人事制度和设备手册等。按视觉结构可分为六类：

1. 合同类：条款密集，关键信息多出现在段落、签章、表格中。
2. 报表类：财务表格与趋势图共存，答案依赖数值和图表标题。
3. PPT 类：页面信息密度较低，但视觉强调和层级结构明显。
4. 单据类：字段固定，金额、申请人、审批状态是高频问题。
5. 手册类：流程图、告警码、步骤说明较多。
6. 制度类：规则表格、条件分支和适用范围较多。

训练样本采用“页面图像、用户 Query、标准答案、相关页面 ID”的结构。每个 Query 可以对应一个或多个正例页面，用于支持跨页检索与生成。

数据质量主要关注：

- Query 是否能唯一定位答案。
- 页面图像是否清晰完整。
- 答案是否可从页面视觉内容中直接推导。
- 是否存在过短、模糊、无业务含义的问题。
- 是否覆盖表格、图表、流程、合同条款等多种视觉结构。

## （3）数据预处理

数据预处理流程如下：

1. 文档脱敏：去除真实姓名、身份证、账号、客户名称、合同编号等敏感字段。
2. 页面渲染：将 PDF、PPT、报表按页渲染为图片，保留表格、图表、版式和颜色。
3. 样本构建：人工或规则抽取页面关键事实，建立页面 ID 与答案证据的映射。
4. Query 扩充：使用 GPT-4o 批量生成多角度 Query，例如事实型、比较型、定位型和跨页型问题。
5. 数据过滤：过滤无答案、答案歧义、页面证据不足、Query 过短或过泛的问题。
6. 数据划分：按文档维度划分训练集、验证集、测试集，避免同一文档泄漏到不同集合。

本工程用 `src/vlm_rag/data.py` 自动生成六类模拟页面图像，并生成对应问答样本。当前包含 18 个页面和 24 条问答，支持合同、报表、PPT、单据、手册、制度六类场景，便于本地直接跑通流程。

## （4）算法设计

整体架构分为三层：页面图像索引层、双塔检索层、多页视觉生成层。

第一层是页面图像索引。系统将文档逐页渲染为图像，为每页建立 `page_id`、`doc_id`、`doc_type`、`page_no`、`image_path` 和业务事实元数据。生产环境中该阶段不依赖 OCR 文本作为主链路，因此可以减少 OCR 误差和版面解析错误。

第二层是双塔图像检索器。文本 Query 进入文本塔，页面图像进入视觉塔，两者映射到同一个向量空间。编码器使用隐藏层加权池化，融合浅层纹理、版式结构和高层语义。训练目标采用 InfoNCE：

```text
L = -log exp(sim(q, p+) / tau) / sum exp(sim(q, p_i) / tau)
```

其中 `q` 是 Query 向量，`p+` 是正例页面向量，`p_i` 是同 batch 页面向量，`tau` 是温度参数。

第三层是多页视觉生成模块。系统对 Top-K 页面逐图推理，再根据检索分数进行加权筛选。生产环境中可以调用 MiniCPM-V 2.6 或 GPT-4o 完成多图问答；本地演示工程使用 `WeightedVisualGenerator` 模拟“检索分数 + 页面事实匹配”的答案融合过程。

运行链路：

1. Query 编码。
2. 页面向量召回 Top-K。
3. 多页候选事实抽取。
4. 检索分数加权重排。
5. 输出答案、证据页面和置信度。
6. 计算 MRR@10、Recall@3、EM、Accuracy。

## （5）重难点分析

难点一是 OCR 误差传导。传统方案先 OCR 再检索，一旦识别错误，后续向量召回和答案生成都会被污染。VLM-RAG 直接处理页面图像，将文字、图表和版式一起编码，降低文本解析错误的影响。

难点二是图文布局丢失。表格中的行列关系、图表趋势、PPT 高亮区域、合同签章位置都属于视觉信息。纯文本切片无法稳定表达这些结构。页面图像编码可以保留原始视觉上下文，使检索更贴近人类阅读方式。

难点三是多页信息融合。企业文档中的答案可能分布在摘要页、明细页、附录页之间。简单图像拼接会导致分辨率下降、上下文拥挤和模型注意力分散。本方案采用 Top-K 逐页推理和分数加权，先保证每页理解质量，再进行答案融合。

难点四是训练数据构建成本。人工标注图文问答成本高，因此需要自动化扩充。通过 GPT-4o 生成多角度 Query，再用规则和模型过滤模糊问题，可以提升样本覆盖度和鲁棒性。

难点五是延迟与成本控制。VLM 推理成本高于普通文本 embedding，因此需要缓存页面向量、离线构建索引、控制 Top-K 数量，并对高频文档进行增量更新。

## （6）总结与收获

本项目构建了一套面向企业内部图文文档的 VLM-RAG 方案。相比传统 OCR RAG，该方案直接基于页面图像进行检索和生成，减少 OCR 误差传导，保留表格、图表、版式等视觉信息，并通过 Top-K 多页推理解决跨页答案融合问题。

工程侧收获包括：

- 检索阶段应优先保证 Query 与页面图像处于统一语义空间。
- 隐藏层加权池化可以增强页面向量对版式和语义的综合表达。
- InfoNCE 适合构造企业文档场景下的对比学习微调任务。
- 多页问答不宜简单拼接图片，逐页推理加分数融合更稳定。
- 数据自动化构建是指标提升的关键，尤其对图表和表格类文档更明显。

本仓库提供的代码是轻量可运行版，用于展示端到端流程。工程中包含数据构建、InfoNCE 训练目标、隐藏层权重搜索、VLM-RAG 主链路、OCR-RAG/SigLIP/ColPali 基线模拟和 CSV 指标报告。生产落地时，可以将本地哈希编码器替换为 MiniCPM-V、SigLIP、ColPali 等模型，将规则生成器替换为 MiniCPM-V 2.6 或 GPT-4o 多图问答接口，并接入 FAISS、Milvus 或 Elasticsearch 向量索引。
